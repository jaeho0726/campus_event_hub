# Campus Event Hub — DataWorks prototype

Runnable Streamlit website MVP based on the DataWorks Workshop 1 notebook and the **Proposal and Build Plan for Campus Org Hub**.

## Get started

```bash
python -m pip install -r requirements.txt
streamlit run app.py
```

The browser will open the website locally (normally at `http://localhost:8501`). For Streamlit Community Cloud, upload the folder to GitHub and deploy `app.py` as the entrypoint.

## Included files

- `app.py`: all website pages and filtering, personalization, event cards, `.ics` calendar download, and baseline metrics
- `events_clean.csv`: 501 deduplicated demo events generated by Workshop 1 Part 6
- `survey_clean.csv`: deduplicated demo survey used only for aggregate baseline indicators
- `events.csv`, `survey.csv`: raw synthetic source data generated by Workshop 1; included for pipeline reproducibility
- `data_pipeline.py`: replay the notebook's Part 6 cleaning pipeline if you update source files (see comments)

## What the prototype can do

- Search event title, club name, and location
- Filter by category, small/medium/large club size, upcoming date, and free food
- Display one card per deduplicated event with location, category, selected start time, and original **platform names**
- Let students choose interests and follow clubs for a session-only "For you" ranking
- Offer an `.ics` calendar invitation with a one-day notification alarm (subject to the calendar application's support)
- Flag the 48 event-time conflicts and explain missing source URLs
- Display survey baselines and the proposal's success targets

## Deliberately not implemented

- No genuine UCSD event feeds. The notebook **generates fictional events** for educational use; the example data runs from September 28 to December 4, 2026.
- No original post links: the dataset has `platforms` but **not URLs**. Link buttons should be implemented after organizers supply verified URLs.
- No automatic email, SMS, or push notification service. Calendar `.ics` is an **add-to-calendar reminder**, not a promise of notification delivery. Events are assumed to last one hour because the dataset does not include end times.
- No login, persistent follows, organizer submissions, live updates, or back-end database. Follows and interests are session-only.
- No actual pilot outcomes, visitor tracking, or proof of causal benefit. Baseline numbers are from synthetic data.

## Recommended next sprint

1. Add a `source_url` and `verified_at` column to a club-maintained event intake schema; confirm verified source and actual time.
2. Add `event_id`, `start_datetime`, `end_datetime`, `updated_at`, and `organizer_contact` columns; move data to a maintained database.
3. Validate design with freshmen, transfer students, and small-club officers; add accessibility and mobile usability testing.
4. Pilot with pre/post surveys; compare to the proposal's missed-event and satisfaction targets before claiming impact.
